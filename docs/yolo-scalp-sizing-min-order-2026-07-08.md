# 极限梭哈仓位与最小下单量优化留档

日期：2026-07-08

## 背景

极限梭哈模式已经切到剥头皮逻辑，但抢跑、火药桶、小仓探路仍可能被旧的探路倍率压得太低。结果是 Dashboard 上看起来有机会，实盘执行时却低于 Binance 最小下单量，或者名义价值太小，手续费和滑点吃掉大部分毛利。

本次迭代把极限梭哈从“旧信号小仓试探”改成“按信号档位给有效仓位，必要时智能补齐交易所最小下单量”。

## 新执行档

仅在 `growth_mode = yolo_scalp` 时启用：

- 标准剥头皮：默认风险区间 `35% - 75%`
- 抢跑剥头皮：默认风险区间 `28% - 65%`
- 火药桶剥头皮：默认风险区间 `30% - 70%`
- 小单探路：默认风险区间 `8% - 25%`
- 亏损后探路：默认风险上限 `12%`，倍率 `0.75x`

高分信号仍会使用原有加仓倍率：

- `yolo_scalp_high_score = 95` 后默认 `1.35x`
- `yolo_scalp_super_score = 118` 后默认 `1.80x`

这些风险百分比是“按止损距离反推的风险预算”，不是简单保证金比例。最终仍受账户权益、最大名义价值、杠杆、止损距离、交易所精度和保护单约束。

## 最小下单量智能补齐

当极限梭哈候选低于 Binance 最小下单量时，系统不再一律跳过，也不会盲目补齐。只有同时满足以下条件才会补齐：

- 当前模式是 `yolo_scalp`
- 已开启 `effective_position_sizing_enabled`
- 已开启 `yolo_scalp_min_order_lift_enabled`
- 候选未因为收益/成本比不足被拒绝
- 补齐后名义价值不超过风险模块给出的最大名义价值
- 补齐后止损风险不超过 `yolo_scalp_min_order_lift_max_loss_pct`，默认 `8%`
- 补齐后成本比不低于 `yolo_scalp_min_order_lift_min_cost_ratio`，默认 `3`
- 补齐后预期净利润不低于 `yolo_scalp_min_order_lift_min_net_profit_usdt`，默认 `0.03U`

如果任何条件不满足，仍然跳过，避免为了满足交易所最小额而把坏单硬塞进实盘。

## Dashboard 变化

极限梭哈下，Dashboard 的“信号类型”会按执行含义显示：

- `standard` 显示为“标准剥头皮”
- `preemptive`、`momentum`、`observe_standard`、`small_standard` 显示为“抢跑剥头皮”
- `extreme_probe` 显示为“火药桶剥头皮”
- `weak_quality_probe` 显示为“小单探路”

配置中心新增了仓位档、亏损后降档、最小下单智能补齐相关参数，默认值已经按当前极限梭哈目标配置。

## 测试覆盖

新增测试覆盖：

- 火药桶在极限梭哈下会得到独立的风险底线。
- 强信号低于交易所最小下单量时，可以补齐到交易所允许的最小订单。
- 补齐后止损风险过大时，必须拒绝下单。

## 风险提醒

这次迭代会让极限梭哈模式更像“短打冲刺”：合格信号的仓位会明显大于之前，反馈更快，但亏损速度也会更快。它适合 0-10000U 的高风险滚仓目标，不适合稳定收益阶段。
