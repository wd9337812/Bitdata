# 2026-07-02 持仓轮换迭代

## 背景

锦标赛阶段默认 `max_open_positions=1`。旧逻辑在已有持仓时会被最大持仓数挡住，即使扫描到更高质量的新信号，也只能等待当前仓位止盈或止损。

本次加入通用持仓轮换引擎：满仓时允许更强的新信号替换弱持仓，但必须通过额外门槛，避免频繁换仓和手续费消耗。

## 默认规则

- `position_rotation_enabled=true`
- 锦标赛、进攻、均衡模式默认允许轮换，稳健模式默认关闭。
- 锦标赛默认要求：
  - 新信号评分不低于 `95`
  - 新信号比当前弱仓评分至少高 `12`
  - 收益/成本比不低于 `8`
  - 当前仓位浮盈超过保证金 `3%` 时保护盈利仓，不轮换
  - 当前仓位浮亏超过保证金 `6%` 时交给原止损，不强制轮换
  - 轮换成功后新旧币种进入 `45` 分钟轮换冷却

## 执行顺序

1. 扫描候选池，选择最高分且通过过滤的信号。
2. 如果未满仓，按原逻辑开仓。
3. 如果已满仓，评估最弱持仓和新候选的分差、成本比、浮盈/浮亏保护。
4. 轮换通过后：
   - 撤销旧仓普通挂单
   - 撤销旧仓条件保护单
   - 市价反向平掉旧仓
   - 开新仓
   - 给新仓挂止损和止盈条件单
5. 如果新仓保护单挂单失败，系统会立即市价平掉新仓，避免裸仓。

## Binance API 注意

币安 U 本位合约条件单已经使用 Algo Order 接口。撤销旧仓保护单不能只调用普通订单撤单接口，还需要调用：

- `DELETE /fapi/v1/algoOpenOrders`

该接口用于撤销指定交易对的所有未触发条件单，包括止盈、止损和追踪止损。

## 风控边界

轮换只在风险层明确传入 `ignore_max_open_positions` 时绕过最大持仓检查。普通开仓仍然受 `max_open_positions` 限制。

本次没有取消止损、每日亏损、冷却、最小下单量、最小名义价值等基础风控。
