# v0.12.0 / V4.3 事件证据与动态准入

## 为什么迭代

V4.2 将实时监控池扩大到 150 个币，但一晚实盘仍只有 3 笔。复盘确认，瓶颈不在“看见的币太少”，而在证据口径和准入结构：

- 同一波行情会在多轮扫描中重复写入影子，样本数被放大，但独立机会没有同步增加。
- `v3_pullback` 与 `pullback` 等同义信号被分成两组，局部证据无法正确合并。
- 大方向或全局 PF 过差时会压住局部新形态，出现“有合格候选但被旧背景一起否决”。
- 小账户也固定要求较高盘口深度，实际只有几十 U 的订单会被不必要地拦截。
- 把广泛下跌视为天然适合追空并不成立。V4.2 数据中该组合扣费后仍为负期望。

因此 V4.3 不再简单扩大币池、降低全部门槛或提高杠杆，而是修正“什么算一笔机会”和“哪一层证据能否决候选”。

## V4.2 复盘证据

V4.2 决策影子共 `4044` 条快照，PF `0.684`、净结果 `-136.291` 个参考单位、估算成本 `97.056`。按 30 分钟、同币种、同方向、同形态、同市场阶段并结合一个风险距离重置去重后，得到 `3727` 个行情事件，PF `0.665`、净结果 `-132.736`。

主要反例：

- `broad_down + SHORT + pullback + RETEST` 且中周期未对齐：`353` 个事件，PF `0.592`、净结果 `-14.921`。
- 对广泛下跌做空进一步做时序两半和特征网格检查，没有找到两半都满足最少 `12` 个事件且 PF 大于 `1` 的稳定子集。

值得进入受限验证的局部组合：

- `quiet + LONG + pullback + RETEST + 中周期对齐`：`25` 个事件，PF `2.751`、净结果 `+4.735`。
- `quiet + LONG + prebreakout + 对齐`：`21` 个事件，PF `1.475`、净结果 `+1.548`。
- 安静行情中对齐的短预突破、长动量、短突破，以及混合行情中对齐的长预突破/突破出现正结果，但各组样本较小，只能进入受限探索，不能直接证明稳定盈利。

将这些历史组合按 V4.3 路由做策略级筛选后得到 `92` 个事件，胜率 `55.4%`、PF `1.794`、净结果 `+9.517`、成本 `2.208`；前后时序两段分别为 PF `1.374` 与 `1.842`。这是同一批历史数据上的反事实筛选，不是完整成交仿真、样本外证明或收益承诺，所以 V4.3 仍从限次许可证和 `0.4x` 开始。

## 事件级证据

- 影子交易按行情事件去重，不再把每轮扫描当成新的独立机会。
- 同币种、方向、标准化形态、市场状态和阶段在 30 分钟内只计一次。
- 当价格相对上次事件移动超过一个风险距离时，视为结构重置，可以重新计入。
- 统一 `v3_pullback/pullback` 等信号别名，准入和复盘使用同一标准形态。
- 历史数据不清空；V4.2 与 V4.3 按精确版本隔离。

## 分层证据与风险

- 当前市场状态、方向、形态和入场阶段的局部证据优先决定候选质量。
- 小样本局部期望使用分层收缩，避免一两笔赢家产生 PF 999 后立即放行。
- 只有同形态局部样本达到默认 `30` 个、PF 低于 `0.50` 且净结果为负，才允许硬阻断。
- 大方向历史较差只把候选风险倍率降为 `0.85x / 0.70x / 0.55x`，不直接否决一个尚无局部历史的新形态。
- V4.3 仍受模型净期望、保守下界、排名、确认数和成本比共同约束。

## 当前实盘路线

核心通道：

- 安静行情中，中周期对齐的做多回踩确认。
- 广泛上涨中，中周期对齐的做多确认回踩或确认突破。
- 仍需通过模型期望、事件证据、排名、成本、盘口和许可证检查。

受限探索通道：

- 安静行情中对齐的动量、预突破及确认后的做空突破。
- 混合行情中对齐的做多动量、预突破或突破。
- 轮动行情中对齐的确认回踩、动量或预突破。
- 默认排名前 `25%`、模型分不低于 `55`、扣费后融合期望不低于 `0.04%`、成本比不低于 `1.60`、至少两项确认、风险倍率 `0.4x`。

仅影子：

- 恐慌行情、逆中周期方向和缺少确认的追价。
- 广泛下跌中的做空在 V4.2 回放里没有稳定正期望，V4.3 暂不实盘。

## 动态盘口门槛

- 先按权益、止损距离、阶段上限和最终风险倍率估算当前通道的实际订单名义价值。
- 最低可见盘口深度默认为 `max(750U, 订单名义价值 × 12.5)`，最高要求封顶 `50000U`。
- 单笔订单不得超过可见盘口的 `8%`，并继续检查点差。
- 该调整只减少“小订单被固定深度误杀”，不会让浅盘口的大订单通过。
- 不新增 Binance REST 深度请求，复用现有竞价盘口快照。

## 性能与 API 开销

- 继续使用 150 币公共 WebSocket 召回，REST 粗排、精排和盘口竞价预算不增加。
- 事件去重在 SQLite 索引和当前开放事件上完成，减少重复影子写入。
- 证据读取上限从 2500 提高到 5000，但使用现有缓存和单次批量查询，不进入逐币 REST 路径。
- Dashboard 只展示聚合漏斗和阻断分类，不拉取更多 Binance 数据。

## 不变的安全边界

- `5U` 权益硬停止不变。
- S0 单仓、风险上限和 `5x` 杠杆上限不因本版本提高。
- 交易所端止盈止损、裸仓补保护和运行时保护不变。
- 最小下单量、点差、盘口占比、手续费与滑点成本检查不变。
- Binance REST 权重、订单频控、公共/私有 WebSocket 兜底和时间同步不变。
- 新版本许可证仍按精确版本限次：一级默认 `0.4x`、最多 3 次，达到亏损预算即撤销；不会主动手工开仓。

## 验证计划

- 单元测试覆盖信号别名、事件去重、价格结构重置、局部证据硬门、方向证据降仓、动态盘口和负期望广泛下跌做空隔离。
- 运行完整后端回归、Python 编译、前端生产构建和本地静态资源 HTTP 冒烟。
- 部署前后查询 Binance 真实持仓、普通订单、条件止盈止损；有持仓时不得为了部署主动平仓。
- 部署后核对 V4.3 路由、精确版本许可证、WebSocket、REST 频控、时间同步、Dashboard 和错误日志。

V4.3 的目标是让“看见更多币”真正转化为“更多独立且可解释的合格机会”，同时避免用更大仓位放大尚未验证的负期望。是否继续放宽或加仓，只能由 V4.3 独立实盘与事件级影子证据决定。
