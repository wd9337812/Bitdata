# Bitdata v0.5.0：V3.1 挑战者、动态退出与 Dashboard 收敛

日期：2026-07-13

## 上线边界

- `extreme_v3_roll` 仍是 S0-S2 唯一实盘策略。
- `extreme_v31_challenger` 只做影子交易，默认 `opportunity_v31_live_enabled=false`。
- 挑战者建议至少累计 100 笔已结束样本、PF >= 1.15、净收益为正后，再单独评估是否晋级。
- 5U 硬停止、每日亏损限制、最小下单量、交易所止损和止盈不允许被挑战者绕过。

## V3.1 中周期层

- 只给精排前 12 个币读取 200 根 1h K 线，不对召回池全量扇出。
- 1h 数据在 runner 内缓存 600 秒；全市场 24h 横截面继续复用 WebSocket ticker。
- 中周期包含 3 日/7 日收益、EMA20/EMA50、EMA20 斜率、横截面分位和价格路径效率。
- 短周期仍使用 V3 的 5m EMA、Donchian、量能、主动成交、盘口和衍生品结果。
- V3 与 V3.1 可对同币、同方向、同信号同时建立影子记录，便于公平对照。

## 动态退出

- 仅升级后新开的 V3 仓位标记为 `v5_dynamic`；升级前已有仓位继续沿用原保护档案。
- 达到保本或跟踪触发条件时，系统先提交更紧的新 STOP_MARKET。
- 再次查询 Binance 确认新止损存在后，才逐张取消旧止损。
- 新单未确认、取消失败、价格不安全或改善距离不足时保留旧保护，并记录状态。
- 止盈单不因止损收紧而删除；保护审计继续保证止损和止盈同时存在。

## Dashboard

- 一级菜单：控制台、机会中心、交易复盘、设置、系统。
- 收益曲线、实盘学习、影子交易和实时风控合并为交易复盘标签页。
- 阶段路线、WebSocket、REST 频控和日志合并到系统页。
- 普通设置只显示当前阶段生效项；旧模式、未来阶段和基础设施参数进入专家设置。
- 删除控制台“产品完成度”和重复市场表；V3.1 样本、胜率、PF、净收益进入复盘页。
- 10 秒刷新调用 `/api/dashboard/live`，只读取本地状态、SQLite 和 runtime snapshot，不访问 Binance。

## API 与性能

- V3.1 最多每 10 分钟为 12 个精排币更新一次 1h 数据，常态新增 REST 权重远低于现有 normal 预算。
- 后台扫描继续使用 background 优先级；快车道使用 realtime；下单和保护使用 critical。
- 手工 `/api/validation/v31` 才会读取长历史，不被 Dashboard 或 runner 自动调用。
- 影子统计按策略族聚合并使用现有 SQLite WAL、索引和留存机制。

## 离线验证

- 新增不使用未来数据的 1h 趋势回放，并与不含路径过滤的普通 Donchian 做对照。
- 结果拆分为样本内 70% 和样本外 30%，扣除手续费与滑点，并输出 PF、净收益和最大回撤。
- 该回放是工程验证工具，不代表完整的幸存者偏差修正研究，也不构成收益承诺。

## 回滚

- 所有新增能力均有独立配置开关。
- 回滚镜像不会删除 V3.1 影子记录；旧版本会忽略新增字段。
- 部署前后必须查询真实持仓、普通订单和条件止盈止损；已有持仓保护不完整时禁止重启。
