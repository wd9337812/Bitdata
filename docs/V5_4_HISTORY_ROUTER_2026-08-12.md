# V5.4 历史正证据全仓短打路由

## 目的

V5.4 不再把所有“顺势突破、预突破或回踩”视为同等机会。它只让历史
实盘中有较稳定扣费后正结果的市场状态、方向和入场结构进入 S0 单仓短打。
其余组合仍会生成影子记录，用于未来验证，但不会消耗实盘本金。

“单仓全进全出”仍表示一个时点最多一仓、可使用约 90% 可用保证金；它不表示
每笔都允许承担 30% 账户亏损。止损账户风险必须由路线、5U 硬停止余量、交易所
条件止盈止损和流动性门共同限制。

可复现的问题，而不是仅由手续费造成。

## V5.4 实盘路线

1. `broad_down + SHORT + pullback + RETEST`：历史最一致，路线风险上限 15%。
2. `mixed + LONG + pullback + RETEST`：历史正证据较强，路线风险上限 12%。
3. `quiet + LONG + pullback + RETEST`：总体仅弱正证据；当前保留为低频路线，路线风险上限 10%。

以下情况只记录影子：追突破/预突破、广泛上涨中的多头回踩、广泛下跌中的多头
回踩、混合市的空头回踩、恐慌扩张。它们可以积累新版本样本，但不能借由旧的
V5.3 回退逻辑直接获得实盘资格。

## 不变的安全边界

- 5U 硬停止、最小下单量、流动性硬门、Binance 频控和时间同步不变。
- 每个真实持仓必须同时有 Binance 条件止损与止盈；运行时保护只会补单或提前退出，不会先撤保护。
- 日盈利锁仍由现有 S0 配置决定；本版本不取消它。
- V5.4 暂不让 V5.3 的全局自适应阈值改写路线，因为 V5.3 的整体样本为负。新版本将单独积累证据。

## 可重复验证

部署后，在 runner 容器中运行：

```bash
python scripts/replay_v54_history_router.py --db data/bitdata.db --holdout-version v5.3
```

该脚本仅统计已记录实盘，不会下单或改配置。
