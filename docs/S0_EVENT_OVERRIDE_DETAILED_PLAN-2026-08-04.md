# S0 事件驱动大不对称详细方案（单仓接管版）

## 0. 目标与边界

- 目标：15U → **10000U（1000x）**。第一桶金 = 10000U，在此之前 S0 全程以事件驱动大不对称为主。
- 边界：5U 硬停止、0.5U 预留、交易所止盈止损、任意时刻最多 1 仓、API 限频。
- 设计：**Phase 0 作为底仓层持续运行；事件通道作为接管层**。事件机会出现并通过全部门槛时，系统平掉底仓、接管仓位；事件结束后回到底仓层。

## 1. 双通道与单仓仲裁

### 1.1 底仓层（Phase 0，持续运行）

- 策略：30 日山寨动量（多空双向）+ BNB 后备。
- 参数：风险 20%（<30U）/ 25%（≥30U）；杠杆 3x；保证金 90%；止损 2.5 ATR；止盈 3.5R；最长 5 天。
- 频率：每日 UTC 00:02 评估；无事件机会时它独占仓位。
- 作用：唯一被审计为正期望的通道；在等待事件期间缓慢复利、防止资金闲置。

### 1.2 事件层（S0 Event，影子验证通过后激活）

- 候选类型：
  1. 新币上市 72h 动量延续（做多/做空）——做多侧是仓库盲区，Phase 1 先补测。
  2. 资金费极端拥挤反转：|funding| ≥ 0.10%/8h + 价格动量衰竭。
  3. 1h 量价爆发延续：5m 成交额 ≥ 24h 均值 5 倍 + taker 失衡 ≥ 0.15 + 30d 动量同向。
- 参数：风险 30%（仅权益 ≥30U；<30U 用 20% 或跳过）；杠杆 3-5x；止损 2.5 ATR；到 2R 保本；10-50R 移动止盈；持仓 1-5 天。

### 1.3 仲裁优先级

**事件 > 底仓**。同一时刻只有 1 仓，事件接管必须显式平掉底仓。

## 2. 事件接管（Handoff）详细规则

### 2.1 事件候选准入（全部满足才可接管）

1. 类型已通过影子验证：该事件类型最近 ≥50 笔闭合影子，PF ≥ 1.2，无 5U 硬停止。
2. 新鲜度：事件触发 ≤ 30 分钟；信号基于已完成 K 线，禁止未来数据。
3. 流动性：24h 成交额 ≥ 2000万U（5x 时 ≥ 5000万U）；点差 ≤ 0.08%；盘口深度 ≥ 2000U。
4. 成本：预期毛利 ≥ 3× 双边成本（开+平+滑点）；预期净收益 ≥ 2× 接管成本（见 2.3）。
5. 账户：权益 ≥ 30U 才启用 30% 档；权益 > 5.5U；当日已实现亏损 < 30% 日初权益；连亏 < 3。
6. 方向门：事件方向与当日 BTC/山寨广度方向不矛盾（模型强信号可豁免，需文档记录）。

### 2.2 接管决策（底仓已有时）

计算底仓当前收益 R：

- 底仓浮盈 ≥ +1.5R：**默认不接管**，除非事件预期 R ≥ 6×（且仍满足成本账）。
- 底仓浮盈在 0 到 +1.5R：事件预期 R ≥ 4× 才接管。
- 底仓浮亏 ≤ 0：事件预期 R ≥ 3× 即接管。
- 事件预期 R 由模型/规则的样本中位 MFE 与计划止损距离计算，禁止用单笔历史极值。

### 2.3 接管成本账

接管总成本 = 平底仓双边成本 + 事件开/平双边成本 + 底仓放弃的剩余期望（按当前浮盈与剩余持有时间估算）。

条件：事件预期净收益 ≥ 2 × 接管总成本，否则不接管。

### 2.4 接管执行顺序（安全优先）

1. 冻结事件快照（价格、ATR、流动性、方向、预期 R）。
2. 平底仓：市价 reduce-only 平仓（先平仓，再撤单，避免无仓条件单悬挂）。
3. 撤底仓 STOP/TAKE_PROFIT 条件单（若平仓后仍存在）。
4. 核对账户为空仓。
5. 开事件仓：设置杠杆（3-5x）、市价开仓。
6. 立即挂事件保护单：STOP_MARKET（2.5 ATR）+ TAKE_PROFIT_MARKET（10-50R 上限）。
7. 更新 state/telemetry：记录接管原因、成本账、事件编号。
8. 全程日志留痕；任一步失败则回滚（不持有裸仓）。

## 3. 事件持仓管理

- 保本：浮盈 ≥ +2R 时，把止损移到入场价（交易所条件单撤销重挂，先挂新止损再撤旧）。
- 移动止盈：浮盈 ≥ +5R 后，止损按峰值回撤 1.5R 追踪（runner 每 30-60 秒检查，WebSocket 价格优先）。
- 上限：TAKE_PROFIT_MARKET 挂在 10-50R（按事件类型），避免单笔利润回吐到零。
- 时间退出：新币动量 3 天、资金费反转 1 天、量价爆发 5 天；到期按市价平仓。
- 事件结束后：清空事件状态，下一 UTC 窗口自动回到底仓层（或 BNB 后备）。

## 4. 底仓层在事件间隙的行为

- 无事件时：底仓层按原规则持有到止损/止盈/时间退出；不主动提前平仓。
- 事件通道每日扫描：UTC 00:02 后每 15 分钟扫描一次候选（WebSocket 流 + 后台 REST 预算），命中即进入接管流程。
- 若底仓当天已开（entry_day 已置位）且事件出现：事件通道不受 entry_day 限制（它是更高优先级通道，接管是平旧开新，不算重复开仓）。

## 5. 影子验证与上线门槛

### Phase 1（研究，2-4 周）

- 数据：1h/1m 点对点、资金费、OI、taker、盘口深度、新币信息。
- 标签：120h 内 MFE ≥ 2×(止损+成本)。
- 特征：横截面动量加速度、量能冲击、taker 失衡、资金费/OI 变化、盘口成本、上市年龄。
- 窗口：2020-2023 开发 / 2024 验证 / 2025 测试 / 2026 盲测。
- 门槛：前 1% 候选扣费后 PF > 基线；逐年为正；去掉头部 1 币仍为正；bootstrap 正概率 ≥ 0.95；无 5U。
- 交付：可复现脚本 + 报告 + 独立影子版本 `s0_tail_event_v1`。

### Phase 2（实盘）

- 影子 2 周：事件类型 ≥50 笔闭合、PF ≥ 1.2、无硬停止。
- 小仓：30% 资金按 30% 风险试 20 笔；达标后全量。
- 未达标：该事件类型永久降级为研究，不上线。

## 6. 风控与硬边界

- 5U 硬停止：触发即平所有仓、撤所有单、机器人暂停，需人工重启。
- 当日亏损 ≥ 30% 日初权益：停止当天新开仓（事件通道同样适用）。
- 连亏 3 笔：事件通道暂停 24h；底仓层按原机制处理。
- 保护单缺失：60 秒内补单；补单失败则市价平仓。
- 最大同时 1 仓；禁止加仓；禁止浮亏补保证金。

## 8. 验收流程

任何改动：前端同步 → 留档 → 全量测试 → 部署 → 交易所保护单复验。

## 9. 风险提示

1000x 是小概率事件；本方案最大化机会的方式是“正期望底仓保命 + 事件接管搏大”，不是保证收益。Phase 1 若两年内找不到跨年正期望的尾部模型，应承认当前规模下 10000U 不可行并停止加杠杆。
