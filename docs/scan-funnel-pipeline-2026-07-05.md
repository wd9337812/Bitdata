# 多模式机会漏斗扫描迭代

日期：2026-07-05

## 目标

把原来的“直接扫描一组币”升级为广告系统风格的 `大召回 -> 粗排 -> 精排 -> 竞价` 管线。目标是在不显著增加 VPS 压力和 Binance API 权重消耗的前提下，让系统看到更多币种和短线机会。

## 适用范围

该管线适用于所有增长模式：

- 稳健
- 均衡
- 进攻
- 锦标赛
- 锦标赛冲刺

不同模式使用同一套结构，但默认预算不同。越激进的模式，召回和精排预算越大。

## 默认预算

全局配置默认值：

- 召回池：`600`
- 粗排池：`220`
- 精排池：`90`
- 竞价池：`15`
- 扫描预算：`18` 秒
- 最低精排：`25` 个币

模式内置兜底：

- 稳健：`180 -> 70 -> 45 -> 8`
- 均衡：`250 -> 100 -> 60 -> 10`
- 进攻：`350 -> 140 -> 70 -> 12`
- 锦标赛：`500 -> 180 -> 80 -> 15`
- 锦标赛冲刺：`600 -> 220 -> 90 -> 15`

## 分层逻辑

### 大召回

从 Binance U 本位 COIN 永续合约里召回更多币种，并优先保留手动候选币。该层只用低成本的 exchangeInfo 和 24h ticker 缓存，不拉 K 线，不回测，不查深度。

### 粗排

使用低成本字段排序：

- 手动候选币
- 24h 成交额
- 24h 涨跌幅绝对值
- 流动性是否达标
- 原始召回顺序的小幅新鲜度加分

粗排只决定哪些币进入精排，不直接决定开仓。

### 精排

只有精排池里的币会拉 K 线并运行当前策略：

- 当前模式策略
- 多空方向判断
- 标准信号
- 锦标赛/冲刺抢跑和动量试探
- 3 天/5 天轻回测
- 收益/手续费滑点比
- 当前模式止盈止损参数

精排层受时间预算保护。系统会优先处理粗排最高分的一批币；当已处理数量达到最低精排数且本轮扫描耗时超过预算时，会停止本轮后续精排，避免 2G VPS 上一轮扫描拖成数分钟。

### 竞价

竞价层限制高成本检查数量，主要控制盘口深度检查。最终是否开单仍由当前已有逻辑决定：

- 币种质量评分
- 盘口深度和点差
- 实盘信用分倍率
- 冷却倍率/熔断
- 当前持仓数
- 换仓逻辑
- 风控限制

## 不变边界

本次迭代不改变最终开单策略，只改变“哪些币值得进入重计算”：

- 不改变实盘下单 API。
- 不改变已开仓持仓和交易所保护单。
- 不绕过信用分、冷却、换仓、风控。
- 不把召回池里的币直接用于开仓。

## Dashboard

多币种扫描页新增“机会漏斗”：

`大召回 -> 粗排 -> 精排 -> 竞价 -> 候选`

用于判断没开仓时到底是没有机会，还是机会卡在某一层过滤。
