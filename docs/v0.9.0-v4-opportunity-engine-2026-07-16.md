# v0.9.0 V4 候选引擎留档

## 背景

V3.2 最近版本和 24 小时影子样本均显示扣费后负期望，而且 A+/A/B 分层没有稳定地把盈利机会排在前面。旧影子模块又只记录已经接近 V3 门槛的候选，因此只能回答“被旧策略看中的机会表现如何”，不能回答“旧策略淘汰掉的机会是否更好”。

这次升级不继续下调某个固定阈值，而是建立独立的 V4 证据闭环。

## V4 决策模型

V4 复用扫描器已经取得的数据，不新增全市场 REST 请求。每个已触发结构按以下信息计算：

- 横截面相对强弱；
- 当前全市场状态与方向是否匹配；
- 放量持续性与主动成交方向；
- 中周期路径效率和趋势一致性；
- 突破延伸、单根冲动和反向影线，防止追在末端；
- 盘口点差、深度与观测到的真实交易成本。

模型先估算扣费后净期望，再给出考虑不确定性的保守下界，并在同一轮候选中计算排名分位。这个分位只比较当时市场里的机会，不再把不同市场状态硬塞进一个绝对分数。

## 三类影子证据

1. **决策样本**：V4 当时排名最高、真正最想交易的少量机会。
2. **探索样本**：从旧门槛拒绝的机会里限量取样。白话讲，就是把以前直接扔掉的机会挑一些“假装做一遍”，检查系统是不是错杀了赢家。
3. **同机会对照**：相同币种、方向和时间，用简单的 1 ATR 止损、2 ATR 止盈趋势突破做基线。只有 V4 长期优于这个简单基线，复杂模型才有存在价值。

每笔样本都记录策略版本、机会 ID、证据类型、手续费估算、滑点估算、市场状态与特征版本。不同版本证据不混用。

## 候选级准入

V4 不再依赖“所有币混在一起的影子 PF”决定是否开仓。未来开启 V4 实盘前，同类候选必须同时满足：

- 首个实盘结构仅限趋势突破；
- 本轮净期望排名进入前 25%；
- 同市场状态、同方向、同结构至少 40 笔证据；
- 扣费后 PF 至少 1.10；
- 保守净期望下界至少 0.02%；
- 满足交易所最小下单量与现有全部执行安全检查。

`opportunity_v4_live_enabled` 默认关闭。达到统计门槛只表示可以人工复核，并不保证未来盈利。

## 性能与 API 开销

- 不新增 Binance REST 请求或 WebSocket 订阅。
- V4 只处理精排后已有候选，时间复杂度与候选数线性相关。
- 历史证据最多读取 2500 笔并缓存 60 秒。
- 每轮默认最多跟踪 3 个决策样本、6 个探索样本和 3 个对照样本。
- 数据库沿用 WAL 和现有维护机制；新增列采用兼容迁移，不清空历史。

## AI 与市场情绪

当前不把大模型放进 5 分钟下单主链路。大模型延迟、输出不稳定且无法凭空创造统计优势，直接投票会降低可回测性。未来若加入新闻或市场情绪，只能作为异步旁路特征，先做版本隔离的影子验证；它可以调整事件风险或暂停特定币种，但不能绕过硬停止、保护单和候选级净期望准入。

## 不变的安全边界

- 5U 硬停止不变；
- 开仓后交易所条件止盈止损不变；
- 裸仓审计与自动补保护单不变；
- 最小下单量、API 限频和时间同步不变；
- V3.2 暂时仍是当前实盘版本，V4 先积累公平样本。
