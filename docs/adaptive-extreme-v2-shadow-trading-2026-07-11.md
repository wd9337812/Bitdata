# Extreme V2 自适应阈值与影子交易实施记录

日期：2026-07-11  
版本：`v0.3.4`  
分支：`codex/two-stage-live-system`

## 1. 问题与根因

VPS 连续观察期间账户权益约为 `29.92U`，机器人保持运行但没有真实开仓。只读诊断确认：

- 旧配置 `tournament_stop_equity=30` 把所有新仓拒绝为 `tournament_stop_equity`。
- 执行器仍继续计算数量与订单可行性，把原始原因覆盖成 `ineffective_order`。
- 标准突破成功对象没有回传 `trend`、`trigger`、`volatility_ok`，行情分类可能把已成立的突破误判为震荡。
- 首轮 VPS 验收发现开仓新鲜度检查曾因缩进错误成为不可达代码，使可执行信号返回 `None`；`v0.3.4` 已恢复该执行链并增加回归测试。

本次同时修复三个问题，禁止再用“最小下单量”掩盖上游风控原因。

## 2. 权益安全线

- `risk_warning_equity=30U`：只告警，继续交易。
- `hard_stop_equity=5U`：禁止新仓、取消挂单、退出真实持仓并进入 `hard_stopped`。
- `hard_stop_recovery_equity=5.5U`：补充资金后仍需 Dashboard 手动启动。
- 风控拒绝后立即返回，不再进入仓位和成本可行性计算。

硬停止退出时先保留现有保护逻辑，逐仓取消相关挂单后市价退出；确认没有持仓后，清理残留普通单和条件单。

## 3. 市场自适应阈值

`app/adaptive_thresholds.py` 只消费扫描器已经取得的 ticker 和 K 线，不发起 REST 请求。

- 全市场 24h 绝对涨跌中位数、75 分位和 90 分位用于划分安静、常态和高波动市场。
- 每个币最近 K 线成交额的中位数和 70 分位用于计算放量基准。
- 放量阈值限制在 `1.2x-2.4x`。
- 火药桶绝对异动阈值限制在 `4%-14%`。
- 安静市场适度降低阈值，高波动市场提高阈值，但任何时候不能突破安全边界。
- 每个候选保存本轮实际阈值，Dashboard 展示市场状态。

## 4. Extreme V2 趋势增强

- 修复标准突破的趋势状态字段丢失。
- 新增 `trend_pullback`：EMA10/20/50 多周期排列、EMA20/50 斜率一致、回踩 EMA10 后恢复原方向。
- 标准趋势保护从 `0.75/1.05 ATR、4 根K线` 调整为 `0.85/1.80 ATR、10 根K线`。
- 抢跑保护调整为 `0.70/1.15 ATR、5 根K线`。
- 动量保护调整为 `0.75/1.35 ATR、6 根K线`。
- 趋势回踩档案包含保本触发和移动止损参数，运行时保护仍负责真实持仓安全。

此调整旨在减少过早止盈，让标准趋势单有空间延续；它不保证提高胜率或收益。

## 5. 影子交易

影子交易是纸面交易：系统记录假设开仓价、止损、止盈和参考名义价值，继续使用扫描行情跟踪，最终扣除模拟手续费和滑点。它不会调用 Binance 下单接口。

- 默认候选最低分 `70`。
- 按模式、币种、方向、信号和 10 分钟窗口去重。
- 默认最长观察 120 分钟。
- 真实交易与影子交易使用独立 SQLite 表。
- 第一阶段影子结果只展示，不修改信用分、实盘仓位或阈值。
- Dashboard 新增中文“影子交易”页面，展示胜率、净收益、成本和每笔结果。

## 6. 性能与 API 约束

- 市场基准由一次 ticker 批量结果计算。
- 币种阈值由已经下载的 K 线计算。
- 影子交易不调用 Binance REST，也不订阅额外 WebSocket。
- SQLite 使用现有 WAL、busy timeout 和短事务。
- 公共/私有 WebSocket、REST 优先级预算和后台扫描降级机制保持不变。

## 8. 风险说明

30U 到 10000U 需要约 333 倍收益，任何自动策略都不能使该目标变得可预期。5U 硬停止意味着最多仍可能损失绝大部分本金；极端行情、滑点、网络故障和交易所执行差异也可能使实际退出权益低于 5U。
