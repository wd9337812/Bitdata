# 动态机会池与模拟准入 2026-07-01

## 背景

上一轮把扫描池扩大后，系统能看到更多币种机会，但也暴露出两个问题：

1. 某些小币种信号分很高，但盘口深度很薄，例如 5 档深度只有几百 U，不适合实盘。
2. 每轮对太多币种做深度检查和多窗口评估，会触发 Binance 访问频率限制。

这次优化的目标是：机会池继续自动扩展，但实盘前必须通过流动性硬门槛，同时控制 API 调用频率。

## 新逻辑

每轮扫描分为两层：

1. 观察层：先用 24h 成交额、K 线、策略信号、3/5 天回测给多币种排序。
2. 实盘层：只有已经出信号或接近触发的候选，才检查盘口深度和点差。

候选池分为：

- `trade`：允许标准实盘。
- `small_trade`：允许小仓试探，自动乘以 `small_trade_risk_multiplier`。
- `observe`：只观察和记录，不实盘。
- `disabled`：暂不交易。

开仓必须同时满足：

1. 策略信号通过。
2. 历史策略回测通过。
3. 币种质量评分达到准入线。
4. 模拟表现达标。
5. 扣除手续费和滑点后仍有足够利润空间。
6. 盘口点差和 5 档深度达标。

盘口是硬门槛。即使评分很高，只要 5 档深度不足或点差过大，也不会进入实盘池。

## API 节流

默认配置改为：

- `max_observation_symbols = 20`
- `max_trade_pool_symbols = 10`
- `depth_check_top_symbols = 8`
- `quality_backtest_days = [3, 5]`

含义：

- 每轮最多观察 20 个币。
- 最多保留 10 个可交易候选。
- 每轮最多对 8 个接近交易的币查盘口。
- 默认使用 3 天和 5 天模拟窗口，降低请求量和计算压力。

如果后续运行稳定，可以再逐步提高观察池；如果再次遇到 418 限流，应先降低 `max_observation_symbols` 和 `depth_check_top_symbols`。

## 评分组成

`symbol_quality.score` 满分 100，主要包含：

| 项目 | 目的 |
| --- | --- |
| 24h 成交额 | 过滤低流动性币 |
| 成交放大 | 捕捉正在活跃的机会 |
| ATR 波动率 | 太低没利润，太高容易被扫 |
| 盘口点差与深度 | 控制真实滑点 |
| 3/5 天回测 | 避免单一窗口过拟合 |
| 趋势一致性 | 当前结构要支持信号方向 |
| 假突破惩罚 | 样本太少、胜率太低、波动过高会扣分 |

## 默认阈值

- 标准实盘：`symbol_trade_score >= 75`
- 小仓试探：`symbol_small_trade_score >= 65`
- 观察池：`symbol_observe_score >= 50`
- 模拟最少信号：`min_simulated_trades = 5`
- 模拟胜率：`min_simulated_win_rate = 45%`
- 模拟 PF：`min_simulated_profit_factor = 1.25`
- 模拟净收益：`min_simulated_net_pct = 1.5%`
- 最大盘口点差：`max_spread_pct = 0.08%`
- 最少 5 档盘口深度：`min_depth_notional_usdt = 20000`

## 对 ZBTUSDT 的修正

旧逻辑里，`ZBTUSDT` 这类币可能因为策略分高、短窗口回测尚可而进入候选前列。

新逻辑会额外检查：

- 盘口深度和点差是否足够。
- 模拟信号数是否至少 5 笔。
- 3/5 天是否同时达标。
- 是否存在高波动假突破惩罚。

如果盘口不达标，即使出现标准突破信号，也只能进入观察池，不会实盘下单。

## 上线注意

本次优化后，机器人仍是每轮动态扫描，不依赖每天批处理。为了避免 Binance 418 限流，部署后如果刚触发过 IP 临时限制，应等限制时间结束后再启动机器人。
