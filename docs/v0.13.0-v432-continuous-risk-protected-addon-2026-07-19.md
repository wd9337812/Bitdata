# v0.13.0 / V4.3.2 连续仓位与受保护追加

## 目标

V4.3.1 解决了旧版本证据混用、全局熔断误伤和许可证无法恢复的问题，但历史样本也证明旧式 A+/A/B 标签不能稳定地代表扣费后收益质量。V4.3.2 不再用离散等级直接决定仓位，而是在候选已经通过 V4 核心准入后，连续衡量机会质量：证据越完整、成本越可控，初始风险越接近上限；证据不足时自然靠近下限。

这个版本仍是极高风险 S0 增长策略，不承诺盈利。它的目的不是每单固定使用大仓，而是让真正通过准入的好机会获得有意义的风险预算，同时把扩大风险的动作放到交易所端保护已经锁定之后。

## 连续质量仓位

连续置信度只作用于 `validated`、`core_provisional` 和 `core_canary` 三个核心通道。`limited_exploration` 继续使用原有受限倍率，不能因为本次升级被放大。

置信度由六个相互独立的部分组成：

- 本轮横截面排名：30%
- 扣费后保守净期望相对成本：25%
- 模型收益成本比：15%
- 中周期方向一致性：15%
- 盘口流动性通过：10%
- 局部熔断未触发：5%

置信度被映射到 `4%-7.5%` 的初始风险区间。方向证据、局部历史、许可证、全局保护、阶段风险上限和账户权益保护仍会继续向下压缩结果；连续仓位不会绕过这些约束。界面中的“强机会/核心机会”只用于中文解释，执行只读取连续数值，不重新建立 A+/A/B 硬分层。

## 盈利后受保护追加

一次持仓最多追加一次，并且必须同时满足：

- 初始机会来自核心通道，连续置信度不低于 `0.75`。
- 扣费后保守净期望至少为估算成本的 `2` 倍，模型收益成本比不低于 `8`。
- 中周期方向、盘口流动性和局部熔断状态均合格。
- 持仓顺向运行至少 `0.55 ATR`。
- 交易所端完整止损已收紧到入场价并覆盖预估成本。
- 当前版本没有触发权益回撤自动回退。

初始风险与追加风险的名义合计绝对不超过 `15%`。追加数量还受初始数量的 `75%`、可用保证金、杠杆、最小下单量和交易所精度共同限制，因此 `15%` 是最坏上限，不是默认目标。

## 交易所保护顺序

单向持仓更换动态止损时，系统先创建并确认一张仅减仓的桥接止损，再撤销旧止损并创建新的完整平仓止损；新止损确认后才撤销桥接单。任何一步失败都会保留已确认的保护，并跳过追加。

双向持仓模式下，Binance 不提供与单向模式相同的原子仅减仓替换能力。系统会保留原有完整止损并拒绝本次动态替换和追加，不能为了多一次加仓制造瞬间裸仓。

追加下单后系统立即刷新真实持仓并审计止盈止损。若完整保护无法确认，只回滚交易所返回的实际新增成交量，不会按计划量误减原持仓。

## 新版本试运行与自动回退

- 许可证精确绑定 `extreme_v4_roll@v4.3.2`。从首次签发起的 24 小时内，无论全局表现保护是否为 `risk_off`，都强制执行首日试运行封顶，旧恢复许可证不能绕过。
- 首日固定使用一级试运行倍率 `0.70x`，最多使用 5 个独立机会；首日内不会因短期盈利自动晋级或提高倍率。
- 发布过程中若已有受交易所止盈止损完整保护的 V4.3.2 持仓，该持仓会被接管为第 1 个试运行机会。在它平仓前不再放行第二个新仓；由于它早于首日许可证签发，也不允许追加风险。
- 两次净亏损后撤销首日许可证，并阻断余下首日窗口的新仓。24 小时窗口结束后，首日封顶自动失效；此后是否允许交易只由当时的全局表现保护、局部熔断和候选自身准入共同决定，不会永久停机。
- 首日 `0.70x` 同时作用于追加总风险上限，因此首日内初始与追加的名义风险合计最多为 `10.5%`，不是完整版本的 `15%`。
- 当前版本记录独立的初始权益和权益高点；从版本高点回撤达到 `8%` 后锁定回退状态。
- 回退后关闭连续仓位放大和追加，恢复核心通道基础受限仓位。该版本回退本身不会触发全局 `risk_off` 或强制冷却；已有的账户级连续亏损、日损和高点回撤保护仍独立生效。切换到新的明确版本才会建立新的版本权益基准，旧版本回撤不会污染新版本。

## 性能与 API 开销

连续置信度复用现有候选特征、盘口检查和本地证据，不新增 Binance 行情 REST 请求。版本权益保护只在权益、高点或回退状态发生有效变化时写入状态文件。追加路径只在已持仓、盈利触发且具备资格时查询保护单和真实持仓，不增加常规 150 币扫描轮次的请求负担。

## 不变的安全边界

- 5U 账户硬停止。
- 任何真实持仓必须同时具备交易所端止损和止盈。
- 最小下单量、价格和数量精度、点差、盘口深度和成本门槛。
- Binance REST 权重、订单频控、公共/私有 WebSocket 与时间同步。
- 部署不能为了重启主动平掉已有受保护持仓，也不能手工制造测试订单。

## 验证口径

V4.3.2 改变的是仓位映射和盈利后追加，不代表已有历史交易可以无偏证明新策略盈利。离线回放可验证风险预算、保护顺序、费用和回撤边界；追加效果仍必须按精确版本隔离，通过试运行许可证下的真实成交和同机会影子样本继续验证。任何 PF 都必须同时报告样本量、成本、净收益和最大回撤，不能仅凭短期高 PF 扩大仓位。

## 线上状态

2026-07-19 已部署提交 `dbd101a`。首日许可证为 `waiting_candidate / 0.70x / 0/5`，机器人运行，Binance 账户空仓且无遗留订单。V4.3.2 的版本权益回退锁此前已经触发，因此当前连续放大和盈利追加按设计关闭，基础受限仓位仍可在许可证和候选准入都通过时执行；该状态不是机器人暂停，也不会由本次热修复擅自清除。
