# 有效仓位与成本准入迭代（2026-07-07）

## 背景

最近实盘订单的平均名义价值偏小，部分订单接近交易所最低下单额。原因不是基础风险不足，而是质量、信用、探路、行情和权益保护等倍率连续压缩。此类订单仍支付手续费和滑点，却很难产生足够净利润。

本次迭代不统一放大仓位，而是让强信号获得有效仓位、弱信号在经济性不足时直接等待。

## 核心规则

1. 扫描器产生的 `risk_pct` 作为候选风险，执行器只应用一次目标进度和权益保护。
2. 信号分为 `probe`、`standard`、`high`、`top` 四档。
3. 极限模式在深度回撤时使用质量感知的权益倍率下限：`0.20 / 0.30 / 0.40 / 0.60`。
4. 最终止损风险下限为：`0.50% / 0.80% / 1.50% / 2.00%`；上限为：`2% / 6% / 10% / 14%`。
5. 最终仓位仍受最大保证金、杠杆、交易所精度和最小名义价值约束。
6. 名义价值低于 `10 USDT`、预期收益成本比低于 `3`、或预计净利润低于 `0.15 USDT` 时不开仓。
7. 不再把低于有效门槛的订单强行抬到 Binance 最低下单额。

## 探路保护

极限火药桶探路单改为：

- 止损：`0.9 ATR`
- 止盈：`1.2 ATR`
- 最长持有：`4` 根 K 线

该调整用于减少 5 分钟级别市场噪声造成的过早止损。弱质量试单继续保留独立参数，避免将弱质量信号与火药桶突破同等对待。

## 可观测性

每次决策新增：

- `effective_risk`：信号档位、候选风险、权益倍率、风险上下限和最终风险。
- `order_viability`：名义价值、收益成本比、预计净利润及未通过原因。
- 扫描前置最小下单检查记录 `effective_risk_pct`，确保候选不会在统一仓位模型生效前被误淘汰。

## 风险边界

- 权益保护达到暂停阈值时仍禁止开仓，信号档位不会绕过暂停。
- 仓位风险下限只在极限模式启用。
- 保护单失败时继续执行原有紧急平仓流程。
- 本迭代提高的是有效资金利用率，不构成盈利保证；极限模式仍可能快速损失全部本金。

## 验证

- Python 自动化测试覆盖档位识别、质量感知权益倍率、风险上下限、成本准入和禁止强抬最小订单。
- 对 VPS 最近 40 个不同候选快照做离线重算：旧模型平均名义价值约 `22.03U`，其中 `15/40` 低于 `10U`；新模型通过样本平均约 `30.23U`，没有低于 `10U` 的订单。
- 典型变化：REUSDT 火药桶候选约从 `11.84U` 调整为 `24.66U`；TLMUSDT 从 `4.65U` 调整为 `13.10U`。风险仍按止损距离和最大保证金封顶。
- 部署前后核对机器人状态、账户权益、当前持仓以及止盈止损保护单。
