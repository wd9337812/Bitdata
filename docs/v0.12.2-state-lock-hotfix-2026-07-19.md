# v0.12.2 跨进程状态锁热修复

## 问题

V4.3.1 首次部署验收时，策略许可证成功记录了新开的 `BANKUSDT` 试单，但局部熔断的持仓归因元数据没有保留下来。交易所端止盈和止损均完整，因此这不是持仓安全故障；根因是 Dashboard 与 runner 两个容器会同时对 `state.json` 执行“读取、合并、替换”，原有线程锁只能保护单个 Python 进程，无法阻止跨容器的短暂写覆盖。

## 修复

- 在 `state.json.lock` 上增加跨进程排他文件锁。
- 每次状态保存都在同一把锁内完成读取、合并、落盘和原子替换。
- Windows 使用 `msvcrt.locking`，Linux/VPS 使用 `fcntl.flock`。
- 状态临时文件在替换前执行 `flush` 和 `fsync`，降低异常重启时丢失最新状态的概率。
- 不修改 V4.3.1 选币、准入、仓位、杠杆、止盈止损或许可证阈值，也不增加 Binance API 请求。

## 回归验证

- 新增 6 个独立 Python 进程并发写入测试，每个进程连续保存 20 次，最终所有进程的字段均保留。
- `python -m compileall -q app tests`：通过。
- `python -m pytest -q`：`252 passed`，仅保留本地 `requests` 依赖兼容警告。

## 实盘处理

部署前后必须重新审计真实持仓及 Binance 条件单。若验收期间已经开出受保护的 V4.3.1 仓位，则只允许从已落库的开仓决策回填局部熔断归因元数据，不得手工开仓、平仓、撤销或重建正常的交易所保护单。
