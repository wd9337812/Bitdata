# v0.10.2 4G VPS 与 150 币实时行情池

## 目标

- VPS 已从 2GB 升级到 4GB，希望把实时监控面扩大到 120-150 个 U 本位永续加密币。
- 扩大“看见异动”的覆盖面，但不把 150 个币每轮全部拉 REST K 线、盘口和回测。
- 不修改 V4.1 评分、准入、仓位、杠杆、许可证或交易所保护单逻辑。

## 资源审计

- VPS 已识别 `3.8GiB` 内存，可用约 `3.1GiB`；CPU 仍为 2 核。
- Dashboard 与 runner 合计内存约 `263MiB`，内存余量充足。
- 磁盘 29GB，已用 16GB，可用 14GB；每日维护定时器继续运行。
- 扩容前公共行情流实际覆盖约 71 个币；后台完整扫描多数为 6-21 秒，已接近 18 秒自动降级线。
- 审计时 REST 交易所额度使用约 42%，内部常规预算使用约 77%，因此不能同步扩大精排和深度竞价。

## 实现

- 新增 `market_stream_min_24h_volume_usdt`，实时池默认可使用 500 万 U 的低成本召回门槛；实盘后台发现仍保留原 `min_24h_volume_usdt=3000万U`，两者完全分离。
- 新增 `market_stream_symbols_per_connection`，默认每组 75 个币。150 币拆成：
  - 2 条 K 线组合流；只有第一条订阅全市场 ticker，避免重复流量。
  - 2 条轻量五档盘口流。
- Dashboard API 新增连接数、订阅数和每连接币数；中文界面显示实际覆盖币数和连接状态。
- WebSocket 事件容量提高到 240，候选读取提高到 80；快车道仍只处理最高优先级 3 个币，盘口精查仍为 3 个。
- 后台 `recall/coarse/rank/auction`、18 秒降级线和 3000 万 U 实盘流动性发现门槛保持不变，防止 REST 额度被扩大后的实时池拖垮。

## Binance 公开行情验证

- 使用真实 Binance USDⓈ-M 公共接口选出 150 个 24h 成交额不低于 500 万 U 的加密币。
- 4 条分片连接全部成功握手并收到首包。
- 150 币合计 451 个订阅：300 个 1m/5m K 线、150 个五档盘口和 1 个全市场 ticker。
- 第 150 名当时 24h 成交额约 601.6 万 U，满足实时池门槛。

## 安全边界

- 实时监控扩大不代表放宽 V4.1 实盘准入；低流动性币仍会被成本、点差、深度和最小下单量硬门阻断。
- 不提高 `rank_pool_limit`、`depth_check_top_symbols`、`fast_lane_max_symbols` 或仓位倍率。
- 不改变 5U 硬停止、最大一仓、交易所端止盈止损、时间同步和 API 限频。
- 扩容部署前后必须检查真实持仓、普通订单和条件订单；有持仓时不得为部署主动平仓。
