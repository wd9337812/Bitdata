# Bitdata v0.6.0：V3.2 证据校准与实盘保护

日期：2026-07-13

## 目标

本版本先修复近期回撤暴露出的执行边界，再优化选币与入场。它不以增加开仓次数为验收标准，而以“同版本、同市场状态、同方向、同入场类型在扣费后是否有正期望”为准。任何策略都不保证收益，也不能保证在指定期限把小额账户滚到目标权益。

## 实盘硬边界

- 实盘短窗口出现严重低 PF、低胜率、连续亏损或窗口亏损达到权益阈值时，影子结果不能否决紧急暂停。
- 24 小时权益高点回撤达到默认 12% 时停止新开仓；已有持仓的交易所止盈止损和运行时保护继续工作。
- 暂停时间到期不等于自动恢复。至少达到二级恢复证据后才允许受限仓位。
- 删除 A+ 绕过全局保护的路径。A+、影子交易、信用分都不能绕过 5U 硬停止、每日亏损限制、保护单和交易所下单规则。
- 实盘换仓默认关闭，保留影子评估开关。手续费、滑点和保护单切换未被稳定验证前不主动平旧换新。

## V3.2 机会准入

- 短周期继续使用 5m EMA、Donchian、量能、主动成交、盘口、资金费率、基差和持仓量。
- 精排前 12 个币复用缓存的 1h 数据，加入 EMA20/EMA50、3 日/7 日动量和路径效率。
- 与全市场趋势相反的方向由扣分改为禁止实盘。
- 恐慌下跌时禁止直接追空，只接受趋势回踩确认。
- 突破或动量信号偏离触发位超过 0.65 ATR，或单根入场冲量超过 1.35 ATR 时禁止追单。
- 突破前预判只进入影子交易；正式实盘必须到达回踩或触发状态。
- 入场状态统一为 `WATCH -> ARMED -> RETEST/TRIGGERED`，Dashboard 会显示当前状态和阻断原因。
- A+ 必须有中周期同向确认。当前版本证据未校准时，A+ 最多按 A 档倍率执行。

## 版本化证据

- 当前实盘版本为 `v3.2`。旧 V2、V3.0、V3.1 数据仅供复盘，不参与 V3.2 放大仓位。
- 证据按策略族、版本、机会档位聚合，并进一步按市场状态、方向和入场类型拆分。
- 默认校准要求：实盘至少 30 笔、影子至少 70 笔、两边 PF 都不低于 1.20，且保守扣费后期望不低于 0.02%。
- 当前版本实盘达到 10 笔且 PF 低于 0.70、净收益为负时，该证据组停止实盘。
- 影子交易记录策略版本、档位和入场类型，避免把不同规则产生的结果混在一起。

## 性能与 API

- WebSocket 继续负责广域 ticker、盘口和事件触发；REST 只用于缓存快照、精选币 1h K 线、衍生品确认、下单和对账。
- V3.2 没有扩大 REST 扇出；中周期仍限制在精排前 12 个币并缓存 600 秒。
- SQLite 结构初始化由“每次连接执行”改为“每进程每数据库一次”，减少高频写锁。
- 高频 `strategy_runs` 默认只保留 2 天，每日最多分四批清理；实盘成交、影子样本和权益记录使用独立留存。
- 决策 payload 只保留候选摘要和最终证据，不再重复存储整个市场宇宙。
- Dashboard 数据库状态缓存 60 秒，行数显示使用主键序号，避免对大表执行 `COUNT(*)`。
- 前端生产包拆分为业务、React 和图表三个 chunk，降低控制台初始解析开销。

## Dashboard

- “实盘学习”改名为“策略证据”。
- 新增 V3.2 证据组、实盘/影子样本、PF、保守期望和校准结论。
- A+ 显示为“待校准机会”，避免把高分误解为已经验证可重仓。
- 候选表显示证据状态或入场阶段，并保留明确不开仓原因。
- 系统页显示数据库、WAL、可回收空间和策略决策序号。
- 删除 A+ 绕过保护和实盘换仓的可见配置项。

## 参考框架

- [Freqtrade Pairlists](https://www.freqtrade.io/en/stable/plugins/)：动态交易池、成交量/涨跌幅/年龄/精度/点差/波动过滤。
- [Freqtrade Protections](https://www.freqtrade.io/en/stable/plugins/#protections)：止损保护、最大回撤、低收益交易对和冷却机制。
- [NautilusTrader](https://nautilustrader.io/docs/latest/concepts/architecture/)：事件驱动、风险引擎和执行对账边界。
- [Jesse](https://docs.jesse.trade/docs/backtesting.html)：回放指标与策略验证工具。
- [Binance USD-M Futures API](https://developers.binance.com/docs/derivatives/usds-margined-futures/general-info)：请求权重、订单频控、WebSocket 和 REST 合约。

这些项目提供的是工程与研究框架，不是可直接复制的盈利参数。V3.2 保留 Bitdata 的小账户、单仓、永续合约和交易所保护单约束。

## 发布与回滚

- 部署前必须暂停机器人并确认真实持仓、普通订单和条件单均安全。
- 生产配置必须显式关闭 `opportunity_v3_canary_bypass_enabled` 与 `position_rotation_enabled`，旧配置文件不会自动被默认值覆盖。
- 大库清理先做备份并验证压缩包，再删除过期高频决策；不得删除实盘成交和影子交易表。
- 回滚到 v0.5.0 时，新字段会被旧版本忽略；V3.2 证据仍保留，但旧版不能读取其校准结论。
