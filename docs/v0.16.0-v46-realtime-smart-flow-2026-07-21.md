# v0.16.0 / V4.6 实时投影与聪明钱软评分

## 目标

解决 Dashboard 持仓保护和机会中心明显滞后、后台全量扫描可能失去响应的问题，并在不增加硬准入门槛的前提下，为 V4 方向判断增加 Binance 官方衍生品数据形成的复合软特征。

## 实时状态架构

- 私有 WebSocket 是账户、权益和持仓的首选数据源；连接心跳新鲜时，没有账户事件代表账户没有变化，不会反复调用 REST。
- 私有账户事件变化后做一次 REST 对账，校准可用余额；WebSocket 陈旧或断线时自动使用 REST 兜底。
- 账户安全监督线程每 2 秒更新 Dashboard 投影。持仓变化时立即检查止盈止损，有持仓时每 10 秒复核，无持仓时每 30 秒轻量巡检。
- 已成交、撤销和过期订单从活动订单缓存移除，避免活动订单数量无限增长；完整历史仍保存在交易和事件数据库。
- `/api/status` 直接读取实时账户投影，不再把上一次扫描保存的权益快照当成当前持仓。

## 扫描自愈

- 全量扫描线程记录开始、完成和错误状态。
- 看门狗每 5 秒检查线程及单轮耗时；单轮超过 90 秒或线程退出时，交易进程以专用退出码退出，由 Docker 重启策略恢复。
- 自愈不把机器人状态写成“暂停”，重启后仍按原运行状态继续；5U 硬停止不受影响。
- 机会中心合并全量排名和 WebSocket 快车道候选，并显示两条链路各自的更新时间和守护状态。

## 聪明钱复合信号

数据来自 Binance 官方 USDⓈ-M Futures 接口：顶级交易者持仓多空比、顶级交易者账户多空比、主动买卖量比和未平仓量历史。

“顶级交易者”是 Binance 按保证金余额划分的前 20% 账户，不等同于确定盈利的钱包。因此本版本只把四类数据组成方向软评分：

- 每轮只深查当前最高排名 12 个币。
- 结果缓存 5 分钟，正常上限约 48 次数据请求/5 分钟。
- 数据源和样本覆盖形成置信度；低于 0.45 时只展示，不参与排名。
- 置信度达标时，按候选方向最多修正 `±5` 分。它不是单独的开仓信号，不能绕过结构、成本、流动性、最小下单量、连续准入和保护单。
- Dashboard 展示偏多/偏空、置信度和实际修正分，便于后续按 V4.6 独立证据复盘。

官方文档：

- https://developers.binance.com/en/docs/derivatives/usds-margined-futures/market-data/rest-api/Top-Trader-Long-Short-Ratio
- https://developers.binance.com/en/docs/derivatives/usds-margined-futures/market-data/rest-api/Top-Long-Short-Account-Ratio
- https://developers.binance.com/en/docs/derivatives/usds-margined-futures/market-data/rest-api/Taker-BuySell-Volume
- https://developers.binance.com/en/docs/derivatives/usds-margined-futures/market-data/rest-api/Open-Interest-Statistics

## 安全边界

- 5U 硬停止、交易所端止盈止损、裸仓自动补保护、最小下单量、流动性硬门、时间同步和 Binance 请求优先级没有降低。
- 聪明钱评分只改变 V4.6 候选相对质量，不提高风险上限，不手工下单。
- V4.6 使用独立版本证据；V3、V4.1 至 V4.5 历史只供复盘，不参与 V4.6 实盘准入。

## 验收

- 部署验收补充覆盖 V4.6 顺势动量分支，避免全量扫描因版本说明变量错误而保留旧快照。
- 后端完整 pytest。
- 前端 TypeScript/Vite 生产构建。
- 本地 API 与静态资源冒烟。
- 部署前后分别查询真实持仓、普通订单、条件止盈止损、机器人状态、版本、WebSocket 和 REST 频控。
