# Bitdata v0.7.0：V3.3 配对影子与版本证据隔离

## 为什么做这次迭代

旧 Dashboard 把不同策略时期的影子结果合在一起。V3.1 的早期盈利可以让累计数字为正，但正在运行的 V3.2 近期窗口可能仍为负，导致“复盘页绿色、首页红色”的理解冲突。更重要的是，旧版本数据不应决定当前版本能否退出 `risk_off`。

截至开发前的 VPS 样本，当前标记的 V3.2 影子约 117 笔，扣费后净收益约 `-1.682 U`、PF 约 `0.83`；同一时期旧 V3.1 挑战者约 97 笔，扣费后净收益约 `-5.275 U`、PF 约 `0.61`。样本足以提出下一版候选，但不足以证明它可以安全接管实盘。

## 版本规则

- `V3.2 / active / live`：当前唯一实盘版本。
- `V3.3-candidate / challenger / shadow`：候选版本，只做模拟。
- `V3.1 / archived`：历史归档，只供复盘。
- 每笔影子和实盘记录保存策略族、版本、用途、发布 ID 和参数指纹。
- 当前策略和候选策略分别计算参数指纹；修改候选阈值不会改变 V3.2 的样本身份。
- 系统没有自动升级策略。候选达标后仍需回测、人工确认、发布新版本并单独部署。

## V3.3 候选逻辑

V3.3 保留成熟趋势滚仓框架中的相对强弱、趋势突破、流动性、真实交易成本与硬保护，并针对现有样本做以下候选调整：

1. 回踩单必须与 1 小时中周期趋势同向，路径效率不低于 `0.18`。
2. 回踩后主动成交方向至少 `0.50`，量能加速度至少 `0.90`。
3. 候选最低收益成本比为 `2.5`，所有影子结果继续扣手续费和滑点。
4. 恐慌行情只验证回踩确认，不直接追突破或动量。
5. 回踩候选止盈为 `2.4 ATR`，最长观察 `18` 根 5 分钟 K 线。
6. 突破、预突破、回踩、动量分别使用专用准入条件，避免一个总分掩盖入场结构差异。

## 公平对照

当 V3.3 发现候选时，系统同时为 V3.2 建立同场基线。两笔记录共享一个 `opportunity_id`，币种、方向、入场类型和时间桶一致，但各自使用本版本的保护参数。实盘下单与影子记账彼此独立，候选不会调用 Binance 下单接口。

晋级前至少满足：

- 已结束影子样本不少于 `300` 笔。
- 连续观察不少于 `72` 小时。
- 扣费后 PF 不低于 `1.15`，且净收益为正。
- 覆盖至少 `2` 种市场状态。

满足以上条件仅代表“可以人工复核”，不代表自动上线。

## 风控口径

- `risk_off` 的实盘、影子和恢复窗口优先只读取 `extreme_v3_roll@v3.2`。
- 当前版本尚无迁移后数据时，保留全历史安全兜底，避免因为迁移空窗错误放行。
- 恢复窗口固定要求最近 `20` 笔当前版本影子证据，净收益为正且 PF 达标。
- 严重实盘亏损与权益高点回撤仍可独立停止新仓，影子候选不能否决安全暂停。

## 性能与 API 开销

- V3.3 复用 V3.2 已有的行情、盘口、衍生品和 K 线快照。
- 1 小时中周期数据沿用小规模精排池与 10 分钟缓存，不扫描完整召回池。
- 不新增 Binance 下单、撤单或账户接口调用。
- 策略注册表只在角色、参数或版本实际变化时写入，避免高频 SQLite 写锁。
- 影子特征只保存精简字段，不复制完整扫描对象。

## Dashboard

- 首页只显示当前 V3.2 的实盘保护和恢复证据。
- 交易复盘新增“策略实验室”，用中文展示当前基线、V3.3 候选和晋级清单。
- 影子明细按策略版本与用途拆分；全历史汇总明确包含归档版本。
- 设置页默认展示 V3.3 配对影子开关，详细阈值收在专家设置。

## 回滚

回滚应用不会删除版本注册、实盘成交或影子记录。若 V3.3 运行异常，可关闭 `opportunity_v33_challenger_enabled`；V3.2 实盘路径和持仓保护不受影响。
