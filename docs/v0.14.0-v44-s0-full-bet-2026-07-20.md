# Bitdata v0.14.0 / V4.4 S0 全仓短打

## 目标与边界

V4.4 仅替换 S0 的机会准入、仓位和快速退出路径。它追求“高质量机会使用大额保证金、快速止盈止损”，不承诺收益，也不把全仓理解为无限杠杆或允许穿透安全保护。

以下硬边界保持不变：

- 账户权益达到 `5U` 时硬停止新开仓。
- 每个真实持仓必须有交易所端止损与止盈；缺失时自动补单。
- 最小下单量、流动性、手续费/滑点成本、API 限频和时间同步继续作为硬门。
- S0 同时最多一个持仓，不做同方向追加；更优机会只有在覆盖平仓、重开手续费和滑点后才允许换仓。

## V4.4 执行模型

- 机会池：公共 WebSocket 最高覆盖 150 个币，常规扫描 120 个币；REST 继续按漏斗精排，避免线性放大 API 开销。
- 准入：方向、市场状态、放量/突破、盘口与成本五类证据中至少满足 3 项，并通过质量、排名、扣费后期望和流动性硬门。
- 资金：默认使用可用保证金的 90%，保留约 10% 缓冲；不是无条件把账户余额全部押入订单。
- 杠杆：根据止损距离和压力成本在 3x-10x 之间动态选择。
- 风险：单笔目标风险按机会连续映射为 8%-15%；计算包含止损距离、往返 taker 手续费、双边滑点，并对成本乘以 1.5 压力系数。任何情况下压力损失不得超过 15%。
- 连亏：连续两笔亏损后，下一笔风险上限自动降到 8%；达到连续亏损底线时停止继续尝试，不使用更大仓追回亏损。
- 退出：初始止损约 `0.85 ATR`，目标约 `1.05R`，到 `0.45R` 后允许移动到保本，最长持仓约 6 根策略 K 线；实时失效信号可触发 reduce-only 市价退出。
- 换仓：新机会相对当前持仓至少多出 `0.35R`，且优势需达到预估换仓成本的 1.25 倍，才允许先平后换。

## 架构处理

- `app/opportunity_v4.py` 负责 V4.4 独立证据、准入和连续风险目标，旧 V3/V4.3 证据不参与 V4.4 实盘准入。
- `app/s0_full_bet.py` 统一计算保证金、动态杠杆、压力成本和 15% 风险硬上限。
- `app/trading_engine.py` 只对已经通过 `full_bet_admitted` 的候选启用全仓 sizing，并维持单仓与换仓成本约束。
- `app/runtime_protection.py` 和 `app/protection.py` 继续维护交易所保护单、保本、追踪与实时失效退出。
- `app/strategy_canary.py` 精确绑定 `extreme_v4_roll@v4.4`，新版本通过独立许可证试运行，不复用旧版本许可证。
- Dashboard 只展示 V4.4 当前通道、全仓利用率、动态杠杆、压力风险和快速保护参数，避免把旧实验结果解释为新版本证据。

## 验收标准

- 完整后端测试、Python 编译、前端生产构建和本地 HTTP/静态资源冒烟必须通过。
- 部署前后都查询 Binance 真实持仓、普通订单和条件止盈止损，不为升级主动平掉受保护仓位。
- 部署后确认 V4.4 路由、许可证、公共/私有 WebSocket、REST 频控、时间偏差、Dashboard 静态资源和错误日志。
- V4.4 的实盘与影子结果按精确版本隔离统计；需要用扣除手续费和滑点后的独立样本判断是否继续，不以单笔盈利证明策略有效。
