# Bitdata v0.15.0 / V4.5 S0 连续准入

## 背景

V4.4 的候选排序和单仓全进全出执行继续保留，但“普通亏损直接撤销许可证、全局冷却、等待影子恢复”的控制方式会让 S0 长时间没有开仓机会。V4.5 将普通交易结果改为连续仓位控制，让惩罚有度，同时保留账户与交易所安全底线。

## 准入与仓位

- V4.5 初始仓位倍率为 `0.75x`。
- 无连续亏损时为 `1.00x`；连续 1/2/3 次及以上净亏损时分别为 `0.75x / 0.50x / 0.25x`。
- 普通亏损不会撤销许可证，也不会触发旧全局、方向或币种冷却。
- 扣费后有效盈利将仓位恢复一级；强盈利或连续两次扣费后有效盈利恢复到 `1.00x`。
- 当日从 UTC 日初权益回撤不足 `10%` 时上限 `1.00x`，达到 `10% / 20%` 后上限分别为 `0.75x / 0.50x`；达到 `30%` 才暂停新开仓。
- 交易结果倍率和当日回撤倍率取更严格的一档，不做连乘，避免仓位被重复压缩。

## 影子证据

真实 S0 同时最多持有一个仓位，因此 V4.5 的当前表现和恢复证据只统计按时间顺序可由单账户执行的非重叠影子交易。与已选影子时间重叠的候选继续保留为研究数据，但不能虚高 PF、撤销开仓权限或恢复权限。

## 保留的硬门

- 候选仍须通过实时触发、相对排名、方向与结构确认、扣费后期望、成本比和流动性检查。
- 保留 Binance 最小下单量、REST/订单频控、时间同步、公共与私有 WebSocket 监控。
- 每个真实持仓必须有交易所端止损与止盈；缺失时由运行时保护补单。
- 权益不高于 `5U` 时无条件硬停止；当日回撤达到 `30%` 时暂停至下一个 UTC 交易日。
- 最大持仓仍为 1；换仓必须覆盖额外手续费与滑点。

## 架构与性能

连续准入只消费已经落库的当前精确版本实盘结果，不增加 Binance REST 请求。状态仅在新成交或档位变化时写入，避免扫描循环高频写盘。V4.5 继续复用 V4.4 的扫描、排序、动态杠杆、保护退出和换仓链路，版本证据与旧版本严格隔离。

## 上线规则

部署时不清空历史数据库，不重置真实当日权益基准。只移除 V4.4 许可证对 V4.5 的旧阻断，并初始化 V4.5 连续准入状态。若部署时已达到 `5U` 硬停止、当日 `30%` 回撤或存在 API/保护单安全故障，则不得强行恢复开仓。
